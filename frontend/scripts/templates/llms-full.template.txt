## 2. Principios de Arquitectura y Buenas Prácticas

1. **La invariante vive en el dato**: Reglas de negocio críticas (descuentos máximos por rol, control de stock no negativo, inmutabilidad de costos de adquisición, triggers de auditoría) se resuelven a nivel de base de datos en PostgreSQL mediante triggers, funciones y vistas con `security_invoker`.
2. **Separación de responsabilidades**: Controladores REST delgados (~10 líneas por acción) que delegan exclusivamente en capas de servicio organizadas por dominio (`Ventas`, `Inventario`, `Finanzas`, `Catalogo`, `RBAC`).
3. **Consistencia bajo concurrencia real**: Uso de bloqueos pesimistas (`lockForUpdate()`) en transacciones de base de datos con reintentos para operaciones financieras concurrentes (abonos, cierres de caja, devoluciones).
4. **Principios FEFO y FIFO**:
   - **FEFO (First Expired, First Out)**: Despacho prioritario de unidades físicas con fecha de vencimiento más próxima.
   - **FIFO (First In, First Out)**: Imputación de pagos entrantes a la deuda más antigua del cliente, previniendo morosidad encubierta.
5. **Seguridad en capas**:
   - **RBAC (Role-Based Access Control)** dinámico mediante Spatie Permissions.
   - **Row-Level Security (RLS)** a nivel de base de datos y aplicación para aislamiento estricto por sucursal.
   - Hardening **OWASP Top 10**: sanitización de entradas, rate limiting, cabeceras de seguridad estrictas (CSP, HSTS, X-Frame-Options), y consultas parametrizadas.

6. **Cultura CI/CD y Automatización DevOps**:
   - **Integración Continua (CI)**: Pipelines automatizados con linters, verificación estricta de tipos en TypeScript/Angular y suites de pruebas unitarias y de integración (como las de Subladmin con PHPUnit, Vitest y PostgreSQL real).
   - **Despliegue Continuo (CD)**: Despliegues condicionados a que esas pruebas pasen, hacia Render, Vercel, Cloudflare Pages y entornos cloud, con el auto-deploy nativo de cada plataforma desactivado.
